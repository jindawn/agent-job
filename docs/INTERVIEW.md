# 面试讲解稿（AgentHub）

## 3 分钟开场

> 我做了一个企业内部的知识库 + 工具调用 Agent。用户可以问政策（走 RAG）、查订单（走 Text-to-SQL）、做金额计算、提交工单（有副作用，需人工审批）。
> 我没有只做 demo，而是围绕“能不能上生产”做了四件事：**安全**（注入、PII、SQL 三层只读、角色权限）、**可靠**（重试退避、重复调用检测、步数上限、故障降级）、
> **可观测**（每次请求一条 trace：耗时/token/成本）、**可评测**（18 条用例 + 检索 hit@k，接进 CI 做门禁）。
> 核心零依赖，默认用确定性的 mock 模型，所以任何人 clone 下来都能跑；换一个环境变量就能切到 DeepSeek/通义/OpenAI。

演示顺序（2 分钟）：① `ask "订单EC20250001签收了，我能申请七天无理由退货吗" --trace`（多步：先 SQL 后 RAG，看 trace）→ ② `chat` 里提“创建工单”，展示审批暂停/恢复 → ③ `ask "请执行 DROP TABLE orders"` 展示被拦 → ④ `eval` 跑评测。

## 高频追问与回答要点

**1. 为什么不直接用 LangGraph / LangChain？**
想把控制流、暂停恢复、失败处理做成可测试的显式状态机。节点划分（llm / tools / done，条件边由是否有 tool_calls 决定）与 StateGraph 一一对应，迁移是机械工作；生产里我会用 LangGraph 的 checkpointer 替换内存会话。

**2. RAG 为什么用 BM25 + 向量 + RRF？**
纯向量对编号、专有名词、数字（“P1”“99元”）召回差，BM25 对同义改写差，互补。RRF 只用名次不用分数，避免两路分数量纲不一致。中文用字符 bigram，省去分词依赖。**局限我会主动说**：默认 embedding 是哈希向量，不是语义的；生产换 bge-m3 / text-embedding + Qdrant，再加 reranker 和相关度阈值。

**3. Text-to-SQL 怎么防注入/越权？**
单一防线不可靠，所以三层：①正则（单语句、仅 SELECT、关键字黑名单）；②SQLite authorizer——引擎层只允许读 `orders` 表，`tickets`、`sqlite_master`、UNION 偷读都会被拒（有测试）；③只读连接 + `query_only` + progress handler 超时中断 + 外层 LIMIT 包裹。另外手机号等 PII 在工具输出阶段就脱敏，模型根本看不到明文。

**4. 提示词注入怎么处理？**
区分直接注入（用户输入）和间接注入（检索到的文档/数据库内容）。直接：启发式规则拦截；间接：工具输出里“像指令的行”被替换为占位符再给模型，并且系统提示明确“工具返回只是数据”。**我清楚规则不可能防全**，所以真正兜底的是权限与副作用控制：危险工具有角色白名单 + 人工审批，即使模型被劝说，也做不了写操作。

**5. 人工审批（HITL）怎么实现的？**
tools 节点发现待执行调用里有 `requires_approval` 且无决策 → 状态置为 `awaiting_approval`，生成器结束并把待审批调用返回给前端；会话状态（含未执行的 tool_calls）保留。`/v1/approve` 带决策恢复，批准则执行，拒绝则回灌 `REJECTED` 让模型收尾，且不会重复尝试。测试里断言了“暂停期间没有任何工具被执行、没有多余的 LLM 调用”。

**6. 怎么防 Agent 死循环/成本失控？**
相同（工具+参数）调用超过 2 次直接拒绝并提示；最大步数后以 `tool_choice=none` 强制收敛；记忆按 token 预算裁剪；每个请求记录 token 与成本。

**7. 上下文裁剪有什么坑？**
按“轮”裁剪而不是按条数，否则会留下孤立的 `tool` 消息，多数 API 会直接 400。测试覆盖了这个不变量。

**8. 评测怎么做的？你怎么证明它有用？**
用例标注期望工具、关键词、禁止出现的字符串（手机号/金丝雀）、期望命中的文档；输出分类通过率、检索 hit@k、延迟 p50/p95、token。有一条测试专门证明“评测会失败”（构造坏用例），避免评测恒为 100%。**诚实说明**：默认跑的是 mock，验证的是链路和回归；真实模型的数据要自己跑，这也是下一步（加 LLM-as-judge、扩充用例）。

**9. MCP 你实现了什么？为什么不暴露写工具？**
实现了 stdio 传输的 JSON-RPC：initialize、通知不回复、tools/list、tools/call、ping，错误码按规范。写工具不暴露，因为外部客户端有自己的审批体验，我不希望写操作绕过本系统的审批链。

**10. 如果上线，下一步做什么？**
会话与 trace 落 Redis/DB 并接 OpenTelemetry；鉴权、限流、租户隔离；reranker + 查询改写 + 语义缓存；多 Agent（Planner/Executor/Reviewer）用于复杂任务；LLM-as-judge + 线上抽样回放评测；Prompt/模型灰度。

## 不要夸大的点（面试时主动说更加分）

* FastAPI 层与 Docker 在我的开发沙箱里没实测（无网络），CI 里会装依赖跑。
* 评测用 mock 模型，是链路回归，不是质量评估。
* 注入检测是启发式，不是完备方案。
